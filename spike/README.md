# Spike — issue #2

> **Question.** Can a pack of usable quality be produced and reviewed to sendable inside
> ten minutes, and does the provenance requirement survive contact with something a
> client will actually read?

Timebox 90 minutes. Private. Not a Tuesday prop.

## What's here

| File | What it is |
|---|---|
| `inputs/` | Synthetic medical brief, CV, and client-knowledge note. **All fabricated** — no real client, candidate, or trust, and no PII. |
| `prompt.js` | The system prompt and user prompt. |
| `schema.js` | The canonical pack + structured-claim schema, for `output_config.format`. |
| `verify.js` | The deterministic literal-quote check (architecture §5.4). No model call. |
| `render.js` | Two renderings of the same pack — provenance inline, and provenance in an appendix. |
| `local.js` | Subscription path: verify + render a pack generated in a Claude Code session. No API key. |
| `run.js` | API path: generate through `claude-opus-5` and measure latency. Needs a key. |
| `pack.json` | The generated pack. Produced in a Claude Code session on 26 July 2026. |
| `out/` | Rendered output. Regenerated by either runner. |

## Running it

```sh
node spike/local.js            # verify + render        (no key)
node spike/local.js --tamper   # prove the check bites  (no key)
node spike/run.js              # generate + time it     (needs ANTHROPIC_API_KEY)
```

## Results so far

**Provenance holds.** 14 claims, all verified against a literal span in the CV or the
client note, or self-declared unverified. The `--tamper` run paraphrases one quote — the
most plausible real failure — and the check demotes it to UNVERIFIED rather than passing
it. That is the difference between a promise and a property, and it is the thing worth
saying in the room.

One implementation note that will matter in #4: quotes must be stored **verbatim** for
the check to work, which means they carry the source document's own line breaks.
Whitespace is normalised for *display* only, never for the value the verifier reads.

## The decision rules (architecture §7)

- Review to sendable needs **more than about five minutes** of human correction → the
  density is wrong and **the pack shrinks before any UI gets built**.
- The output **reads like a compliance form** rather than a submission → provenance moves
  to a footer or appendix and stays out of the body. Both renderings exist so this is
  settled by comparison. Whichever you would actually send becomes #7's default.
- Both hold → build B as specced.
- Latency eating the budget → **effort is the lever before the pack shrinks.**
